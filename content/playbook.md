# WeWrite Playbook — 作者

> 从用户对生成稿的修改/反馈中沉淀的写作规则。按 confidence 分级:
> - confidence ≥ 5: 硬性规则,优先级高于 persona 和 writing-guide
> - confidence 1-4: 软性参考

## R001 — 不要"唱苦情戏"

**confidence**: 6 (用户原话明确否决,首次出现)
**date_added**: 2026-04-18
**source**: 用户对 v1 稿件的反馈("你在唱苦情戏么 还凌晨 2 点开头。。。我受不了前面阶段内容。专业点就行了")

### 规则

**禁止**以下"装腔作势的人格化"写法:

| 禁止类型 | 反例(v1 出现过) | 正确做法 |
|---------|----------------|----------|
| 凌晨/深夜场景开头 | "凌晨两点多。我刚提了一个 PR..." | 直接进项目复盘或事实陈述 |
| 装腔作势的自我怀疑 | "我有点不确定了。" / "也许我想多了。" / "我承认我也看不清楚。" | 直接给判断,有把握就有把握说出来 |
| 情绪化的内心描写 | "那一下我没什么情绪。或者说 — 不对,是有的。是一种安静的、有点冷的感觉。" | 用事实和数据说话,情绪用一句结论收掉 |
| 空泛的存在主义喟叹 | "这话说出来其实挺残忍的。我也不愿意这么想。" | 砍掉,直接陈述判断 |
| 不收束的 trailing-off 收尾 | "也没觉得特别兴奋。就是,有点想再改一个。" | 给具体动作建议或落到锐利结论 |

### 替换原则

**调性目标**:**专业观察者**,不是"深夜倾诉的设计师朋友"。

- 第一人称仍可保留,但用于陈述项目和判断,不用于自我审视
- 数据先行,情绪服务于论点而非取代论点
- 收尾要有"action item"或锐利结论,不要"飘走"

### 对 persona / score 的影响

- midnight-friend persona 的 `uncertainty_rate=0.15` 对 作者 失效,降到 ≤0.05
- midnight-friend 的 `closing_tendency=trailing_off` 对 作者 失效,改为 action_oriented
- humanness_score 中 `self_correction` 和 `negative_emotion_ratio` 的低分**不参与**优化决策(因为这两项强行拉高就会回到苦情戏)

## R003 — 名词类章节要"摆出来对比"

**confidence**: 5
**date_added**: 2026-04-18
**source**: 用户明确要求("加入对于未来设计师定位的名词描述,比如 builder")

### 规则

涉及行业新概念/新角色名时,不能只丢一个词,要做**多候选对比表**:

| 列要素 | 内容 |
|-------|------|
| 称谓 | 名字 + 中文翻译 |
| 出处 | 谁在用 / 哪家公司在用 |
| 强调什么 | 核心语义 |
| 局限 | 用这个词的代价是什么 |

最后给**自己的判断** — 哪个名词在哪个时期最合适。

### 适用场景

- 角色/职位演化(Builder / Product Engineer / Design Engineer)
- 工具/产品类比(Cursor / v0 / Lovable)
- 方法论/流程(Double Diamond / Lean / Agile / AI-native)

## R004 — 流程对照类章节要带视觉

**confidence**: 5
**date_added**: 2026-04-18
**source**: 用户明确要求("把现在和未来的设计流程要做成一个章节,并有配图辅助")

### 规则

写到"新旧对比/前后变化"类内容时,**必须**有视觉辅助:

1. **首选 ASCII 流程图** — 文章内直接可见,渲染时变 code block,既保留信息又不依赖图片
2. **配套图片提示词** — 给出 Rokey 风格的插画 prompt,可后期生图替换
3. **必有总结对照表** — 行=维度,列=新旧两态

### 模板

```
### 旧流程: [一句话定性]
[ASCII 流程图]
[一段话解读]

### 新流程: [一句话定性]
[ASCII 流程图]
[一段话解读]

### 关键差异一表看完
| 维度 | 旧 | 新 |
|------|----|----|
| ... | ... | ... |

> 📌 配图位: [Rokey 风格插画 prompt]
```

## R005 — 收尾要"行动导向",不要"飘走"

**confidence**: 5
**date_added**: 2026-04-18
**source**: 与 R001 共同推导

### 规则

文章收尾必须满足以下之一:

- 给出 N 个具体动作(如本篇 §五 的"三个动作")
- 给出锐利的二选一判断("你想做名字带 X 的人,还是名字带 Y 的人")
- 给出可量化的预测("未来五年,这一行会 ...")

**禁止**的收尾形态:
- 风景描写、场景渐隐
- "我也不知道"式的悬置
- "让我们拭目以待"类的废话
- "继续画稿/继续工作"的循环回归

## R006 — 观点型文章必须围绕"明确的核心论点矩阵"组织,不堆砌相关章节

**confidence**: 5
**date_added**: 2026-04-18
**source**: 用户对 v2 反馈("未来设计师的名词候选完全不需要,你要讲设计师的交付从高保真的静态设计稿转向了什么,从而引出 builder 的角色就行。这篇文章核心的观点:1.设计师的交付标准变化;2.设计工具的变化;3.设计流程的变化")

### 规则

观点型文章在写之前必须先**列出 2-4 个核心论点**,每个论点对应一个独立 H2 章节。**禁止**:

- 把"对相关概念的科普/罗列"当成独立章节(如"未来设计师的名词候选"6 词对比表) — 这种内容应当**作为论点的论据**自然嵌入,不另立章节
- 章节之间是"信息平铺"而不是"论点推进"关系
- 出现"看起来很丰富但抽掉一节也不影响主线"的章节

### 正确做法

1. **先写论点矩阵**:用 2-4 句话写出文章的核心主张,每句一个论点
2. **每个论点 = 1 个 H2 章节**
3. **论点之间必须有"逻辑咬合"**:章节 A 的结论是章节 B 的前提,删掉任何一节主线就断
4. **新概念/新名词从论点中自然引出**,不单独立章节摆名词卡片

### 案例对照

| 反例(v2) | 正确(v3) |
|----------|---------|
| §一 行业信号 / §二 流程对照 / §三 名词候选 / §四 我的项目 / §五 三个动作 | §一 行业信号 / §二 交付变化(引出 Builder) / §三 工具变化 / §四 流程变化(含对照图) / §五 我的项目验证三件事 / §六 三个动作 |
| 名词候选是"摆 6 个词对比" — 信息平铺 | Builder 从"交付物从静态稿变可跑代码"自然推出 — 论点结论 |

### 与 R003 的关系

R003 ("名词类章节要摆出来对比") **不撤销,但限定适用范围**:仅当用户明确要求"做名词梳理"或文章主题就是名词辨析时使用。在论点驱动型文章里,名词应作为论据,不另立对比章节。

## R007 — 固定写作偏好 + 去AI味流程(2026-10-12)

**confidence**: 6 (用户明确决定:"中英之间不加空格,这条已定,直接执行,不用再问")
**date_added**: 2026-10-12
**source**: 用户批准的去AI味升级(研究报告 ${WORKSPACE}/de-ai-research/report.md),与 R001 同方向

### 规则

1. **语体**:中文顺、自然,标准技术书面语;不要翻译腔,也不要纯口语。术语用行业标准叫法,首次出现解释一句,全文统一
2. **禁止**:"不是…而是…"套话;正文出现公司名/项目名;"本文为 AI 辅助创作"类声明;小标题"一、二、三"编号;中文与英文/数字之间加空格
3. **排版紧凑**:段间只空一行,粗体 ≤5 处,能写段落就不拆列表
4. **不装人味**:不加"嗯。"单句段、表演式纠错、生造词、随机类比、固定金句位、负面情绪配额。读者能看出来,这本身就是 AI 味
5. **正式稿 → 推送之间必须走 8 步去AI味流程**(见 writing-guide.md「去AI味流程」)。X 英文版从大纲直接用英文写,不翻译中文终稿

### 与 R002 的关系

R002("个人项目要用真实场景做切入")**保留场景,隐去名字**:真实的数字、卡点、耗时照写,但项目名/公司名换成描述("我的个人知识库""一套自动化 QA 系统")。

## 图片套装规则（2026-10-17）

- 中文套：微信封面 2.35:1（2350×1000）+ 方形封面 1:1（1000×1000，缩到 200/120px 检查核心符号可读）+ 内文配图；X 不出中文版。
- 英文套：X header 1500×600 + 内文配图。
- 同语言封面变体元素一致，只缩放/重排不删内容；方形封面例外：不放标题文字，只留一个核心符号/数字 + 视觉母题（底图/网格/橙线/目标框）。
- 推草稿：`cli.py publish --cover <2.35:1> --cover-square <1:1>`（自动拼图 + pic_crop_1_1）。详见 SKILL.md Step 6.2。
