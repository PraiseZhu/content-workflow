# 公众号周选题自动化 · 设计文档

> 一句话：每周六 22:00 一个定时任务从 <agent> 一周活动里挖出 ≥10 张「证据包+标题+提纲」选题卡；你周日筛选并丢观点；同一个交互会话完成提纲重构→实战风格成文→去 AI 味→配图排版→推草稿箱→自动打开公众号后台等你点发布。

---

## 1. 目标与成功标准

**目标**：把「一周实战 → 公众号文章」的链路自动化，人只做三次判断：选题、确认全文、点发布。

**成功标准（全链路验收）**：
1. 周六 22:00 任务无人值守跑完，产出 ≥10 张达标选题卡，落盘 `公众号/selections/`，桌面通知送达
2. 选题卡上每条提纲节点都挂有具体证据引用（session id / commit / 报错原文），无空心选题
3. 从「选 N + 丢观点」到「草稿箱有排版好的文章 + 后台页面自动打开」，中途只需两次确认（提纲、全文）
4. 成文自动通过 6 硬门槛自检 + 脱敏黑名单 grep 检查
5. 全程不出现取材红线违规（见 §3）

---

## 2. 目标文章标准：AI 实战型干货（选题准入 + 成文自检共用）

**定位**：AI 时代设计师的实战工作流——一手机制、真实故障、可抄走的做法。不写概念科普、不做信息搬运。

### 6 条硬门槛（同时满足才达标）

| # | 门槛 | 机器判定方式 |
|---|------|-------------|
| 1 | 一手战场：核心案例是自己动手做过的具体行动 | ≥3 处「我改了X/我加了Y/我发现Z」且 X/Y/Z 是具名文件、字段、脚本、命令 |
| 2 | 有故障现场：≥1 个真实失败→诊断→修复闭环 | 存在「原以为…实际是…」或具名报错原文 |
| 3 | 能抄走：给出可直接复制使用的东西 | ≥1 个代码块/字段清单/检查项列表，读者复制能用 |
| 4 | 自有数字：≥3 个自己系统测出的量化事实 | 数字来源是自有系统（session 数/commit 数/拦截次数），非引用报道 |
| 5 | 一条咬合的主线：2-4 个论点，抽掉任一节主线断 | H2 序列做「前节结论=后节前提」检查（playbook R006） |
| 6 | 收尾落到动作 | N 个具体动作 / 锐利二选一 / 可量化预测（playbook R005） |

### 红线预筛（借鉴 <ChatTool>「红线命中即淘汰」结构，选题阶段一票否决，不进候选池）
- ❌ 主要案例是别人的产品发布 / 博客 / 书
- ❌ 提纲凑不出满足门槛 1+2+3 的具体素材
- ❌ 命中 §3 取材红线（业务数据 / 未脱敏公司信息）
- ❌ 命中微信平台合规红线（见 §3 Layer2）

## 3. 取材红线（用户 2026-07-25 拍板，已存 memory `feedback_wechat-article-redlines.md`）

### 进池规则（选题阶段拦截）
- ✅ 机制类可写：流程设计、hook/拦截规则、agent 编排、review 链、prompt 工程、工作流方法论
- ❌ 业务数据不进证据包：功能名、业务指标、上线计划、用户数据、界面细节
- <ImageGenCanvas> 来源素材：机制类可入池，选题卡上预打码为「一个内部项目」

### 成文脱敏（生成阶段硬规则 + 机械兜底）
- 一律不出现：公司项目/仓库名（含 <AGENT>、<agent-moved>、<ImageGenCanvas>）、内部服务域名、同事名、内部群名 → 统一泛化「一个公司项目」
- 数字只用自有系统运行数字，不用业务指标
- **推送草稿箱前跑黑名单词表 grep，命中即拦**（系统拦截，不靠模型自觉）
- 黑名单词表 `公众号/automation/blacklist.txt`，**两层**（借鉴 <ChatTool> 违禁扫描 + 爆款炼金师风险清单 10 类）：
  - **Layer1 公司脱敏词**：项目名、域名、人名、内部群名（可随时追加）
  - **Layer2 微信平台违禁词**：广告法绝对化词（最/第一/唯一/顶级 → 之一）、震惊体疲劳词（震惊/不看后悔）、医疗敏感、政治敏感、诱导分享词。防被微信审核打回或限流

> ⏳ 待确认：<AGENT> 是否可以作为工具名出现（如「我在 <agent> 里建了个定时任务」）。当前从严默认：不出现。

## 4. 全流程架构

```
┌─ 阶段1 · 周六 22:00 定时任务（无人值守）──────────────────────┐
│ 取数(session+git+运行统计) → 过滤 → 聚类 → 深挖证据           │
│ → ≥10 张选题卡（滚动池补足）→ 落盘 selections/ → 桌面通知     │
└──────────────────────────────────────────────────────────────┘
        ↓ 周日你说「本周选题 选 3」+ 丢观点想法
┌─ 阶段2-5 · 同一交互会话（wewrite 改造版）─────────────────────┐
│ ② 你的观点为主导重构提纲        ← ✋确认点1：提纲              │
│ ③ 实战风格成文（证据包为素材源）← ✋确认点2：全文              │
│ ④ 去 AI 味润色（换家族模型，只动文风不动事实）                │
│ ⑤ image-gen 出图(Claude X 风格) + claude-warm 排版                 │
│    → 脱敏 grep → 推草稿箱                                     │
│ ⑥ open mp.weixin.qq.com        ← ✋确认点3：你手动点发布       │
└──────────────────────────────────────────────────────────────┘
```

发布永远人工点。系统最后一步只负责把后台页面推到面前。

## 5. 阶段 1：周选题定时任务

### 5.1 调度参数（<scheduler>.schedule_create）

| 参数 | 值 |
|---|---|
| name | 公众号周选题 |
| cronExpr | `0 22 * * 6`（周六 22:00） |
| timezone | Asia/Shanghai |
| recurring | true |
| agentKind | claude-code |
| model | claude-fable-5（实施时以网关实际 id 核对） |
| workingDir | `${CONTENT_ROOT}` |
| notify | desktop: true |
| prompt | 「调用 idea-outline skill 并严格执行」 |

数据窗口：上周六 22:00 → 本周六 22:00。任务逻辑全部写在 runbook 里（可版本化、可手动触发同一份逻辑做 dry-run）。

### 5.2 取数三层

1. **入口层（runbook 内嵌确定性脚本，非 LLM 判断）**：`list_sessions` 拉 7 天全量 → 机械过滤：`source=scheduler` 剔除、标题 `Worker ·` 前缀剔除、`messageCount<10` 剔除。约 200 → 40-60 个有效 session。
2. **证据层（重点投入）**：标题聚类出 12-15 个「本周事件」；每个事件用 `search_chat_history` 挖对话细节（报错原文、决策理由），`git log -p` 取真实 diff（过滤「本轮开始前的未提交改动」自动提交）。git 取证范围：Project <AGENT>、<ImageGenCanvas>（素材预打码）。
3. **数字层（免费）**：session 数、消息量、模型分布、commit 数——本身就是门槛 4 的自有数字。
4. **纵向层（深度的来源）**：读 `automation/trajectory.md`（跨周数字账本 + 主题线索账本，本任务每周自动维护）与 `automation/baseline.md`（无 AI 时代的传统工时基线，用户一次性填写、逐周校准）。单周事件只有放进跨周曲线和传统基线的对照里，才能长出行业级判断——深度不来自单周快照，来自纵向积累。

### 5.3 选题卡 schema（固定结构）

> **核心原则（用户 2026-07-25 强调）：选题的卖点是「行业判断」，不是「我做了什么」。**「我做了 X 项目」只是内部燃料/证据锚点，**不作为标题、不作为文章开头、不作为卖点**。选题卡以 L3 判断为标题，L1 事实降级为内部证据字段。搬运活动 = 废稿。

```markdown
## 选题 NN ｜ 优先级 S/A/B
- 【选题主张】…（这就是标题方向：一句 L3 行业判断，如「设计师的交付物正从稿子变成规则」。禁止写成「本周我做了 X」）
- 思考阶梯（强制爬满三层，缺层即降级）：
  - L1 事实（仅内部燃料，不进正文开头）：这一/几周我做了什么（带数字）
  - L2 模式：这说明工作方式发生了什么**结构性**变化
  - L3 判断（= 选题主张）：对设计师职业/行业意味着什么（可证伪的表述）
- 最反常识的观点：…（站在 L3 输出，禁止停在 L1 复述事实）
- 与 AI 时代设计师工作的关系：交付标准 / 定位 / 交付物 / 人才画像 哪一项被重写
- 可用数据和证据（埋在论证里，不当卖点）：
  - commit <hash>「<摘要>」（diff 要点附后）
  - session「<标题>」中的报错原文/决策对话
  - 运行数字 + baseline 对比（无 AI 时代几人几月 vs 现在）：…
- 建议标题（3 个变体）+ 标题评分（借鉴 <ChatTool> 爆款炼金师的「打分卡+硬阈值」结构，换成实战干货维度）：
  - 6 维各 1-5 分（具体度 / 可信度即一手证据强度 / 反常识强度 / 搜索友好 / 情绪节制 / 长度适配，公众号标题黄金 18-24 字）
  - 总分阈值：≥26 直接立项 / 20-25 建议再打磨 / <20 换角度。3 变体至少用 3 套不同标题公式（数字清单/反常识断言/避坑警告/自问自答，砍掉震惊体猎奇向）
- 传播潜力：S/A/B + 一句话理由
- 门槛自评：①一手 ②故障 ③可抄 ④数字 ⑤主线 ⑥收尾（✅/⚠️缺什么）
- 脱敏项：…（成文时需替换的词）
```

**优先级规则**：S = **爬到 L3 + 有基线对比数字** + 门槛①②③④全齐；A = 门槛齐但停在 L2；B = 缺 1 项门槛或停在 L1（标出缺什么）。排序 S→A→B。

**卡片分两类**：
- **单周事件卡**：本周一次具体行动长出的选题
- **主题发育卡**：trajectory.md 里跨周线索攒到「可写时刻」的选题（例：连续 4 周都在建拦截规则 → 「设计师的新产出物是规则，不是稿子」）。**深层选题主要从这里长出来**——每周任务检查各主题线索是否已攒够证据，够了才发卡，不硬憋。

### 5.4 滚动选题池（≥10 保障，用户已拍板）

- 每周新选题追加进 `selections/pool.md`
- 当周新产 <10 → 从池回捞往周未选中且仍成立的选题补足，标注「回捞·Wxx」
- 你选中/明确毙掉的从池中移除；不降门槛、不硬凑

### 5.5 深层思考协议（runbook 强制执行）

每个候选选题在成卡前必须回答 5 问，答案直接喂进思考阶梯：

| # | 问题 | 作用 |
|---|------|------|
| 1 | **对照问**：这件事在没有 AI 的时代需要几个人、多久、什么质量？ | 引用 baseline.md；无对应条目则给保守估算并标「⚠️待校准」，你筛选时顺手改一个数 |
| 2 | **性质问**：这是「变快了」还是「性质变了」？ | 只是快 → 选题降级；交付物/角色/标准变了 → 升级。防止把效率文写成深度文 |
| 3 | **角色问**：谁的工作因此被重新定义？ | 设计师/评审/PM/工程师——逼出人才画像和定位判断 |
| 4 | **代价问**：这个变化的反面代价或新风险是什么？ | 防吹捧，保诚实——单向叫好的判断不可信 |
| 5 | **预测问**：给一个可证伪的预测 | 「未来 X 会 Y；如果出现 Z 现象说明我错了」——L3 判断必须能被打脸 |

### 5.6 产物落盘

- `公众号/selections/2026-Wxx-选题.md`：当周 ≥10 张卡 + 证据附录（diff 摘要、对话摘录、数字表）
- `公众号/selections/pool.md`：滚动池
- `automation/trajectory.md`：追加本周数字账本行 + 更新主题线索状态（每周自动维护）

## 6. 阶段 2-3：筛选与成文（交互，复用 wewrite）

### 6.1 入口

任意 <agent> 会话说「本周选题」（列出当周卡片）或「本周选题 选 3」+ 观点想法。实现为 wewrite SKILL.md 辅助功能新条目 + `references/weekly-topics.md` 流程文件——不新建管道。

### 6.2 观点合并逻辑

1. 读选题卡 + 证据附录
2. **你的观点做主导**：你的判断覆盖卡上的「反常识观点」，提纲围绕你的观点重排
3. 证据重新分配到新提纲各节；缺证据的节明确标「⚠️ 此节无一手证据，补或删」——防空心稿
4. ✋ 确认点 1：提纲

### 6.3 成文（wewrite Step 3→4，两处改造）

- **素材源改造**：从「WebSearch 全网」改为「读证据包」，网搜仅作补充佐证
- **风格锁定**：《目标驱动链》为基准范文 + playbook R001-R006 硬约束 + §2 六门槛作为成文自检清单
- ✋ 确认点 2：全文

### 6.4 去 AI 味润色

- **换家族模型执行**（见 §8）：同模型自润，token 分布指纹仍在；换训练分布不同的模型重写表层文风，统计特征才真正打散
- **原则「风格只影响 HOW，不影响 WHAT」**（借鉴 <ChatTool> ToneStyle 注入机制）：只动文风（句长/口语/节奏），事实与数字锁死不动（事实层在证据包里有据可查）
- **去 AI 味禁忌表**（合并三处提取，落 playbook）：
  - 来自 humanizer（有出处，基于 Wikipedia「Signs of AI writing」）：禁 inflated symbolism、宣传腔、浮浅的 -ing 分析、模糊归因、破折号滥用、rule of three、AI 高频词、否定排比、过度连接词
  - 来自爆款炼金师 Pitfalls：禁 B 端黑话（赋能/抓手/闭环）、禁震惊体、一句最多 1 个强情绪词、人设专业冷静克制
  - 来自 bundle AI-tells：禁通用名、禁假数字（凑整的 99.99% → 用真实的 47.2%）、禁填充词（Elevate/Seamless/Next-Gen → 具体动词）
  - 这三组与你 playbook 的 R001「禁苦情戏、做专业观察者」同向，合并即是加强版

## 8. 模型路由（3 chat + 1 图像通道 + 2 段零模型）

| 环节 | 模型 | effort/fast | 理由 |
|---|---|---|---|
| 取数过滤 | 无（确定性脚本） | — | 字符串匹配不给 LLM |
| 聚类（session 标题归主题） | **claude-opus-5**（与深度选题同会话） | max / 关 | **2026-07-25 A/B 实测改定**：原定 gemini-3.5-flash/high，实测它忽略输入的 msgs 数字字段、L3 全是行业黑话；opus-5 主动用消息数当论据、判断可直接用。聚类输入仅几千 token，省钱意义 ≪ 质量差距。副作用：无需 gemini 网关旁路，架构简化 |
| ① 深度选题生成 | **claude-opus-5** | **max / 关** | 用户点名。深度思考出行业判断，整链天花板 |
| ② 提纲重构 | **claude-opus-5** | **xhigh / 关** | 用户点名。逻辑+结构+事实忠实，不能写飞 |
| ② 成文 | **claude-fable-5** | **xhigh / 关** | 用户点名。语气还原+叙述手感，创意写作最强档 |
| ③ 去 AI 味润色 | qwen3.7-max（省钱档 glm-5.2） | 不传 effort（2026-07-25 实测：worker 通道该模型无 effort 档位 valid:none） | 换家族打散统计指纹 + 中文口语最强档；实测通过：事实 3/3 锁死、AI 味 6/6 消除、字数 -53% 属预期特征 |
| ④ 配图 prompt | 主会话顺手 | — | C 级任务不单配 |
| ④' 出图 | image-gen 通道（MJ/niji） | — | 用户已定 |
| ⑤ 排版/推送/开后台 | 无（脚本） | — | 确定性操作 |

模型 id 已对网关可用列表核对（claude-opus-5 / gemini-3.5-flash / qwen3.7-max 均在）。用户点名项（opus-5 max / opus-5 xhigh）为第 0 优先，不降档。

## 9. 前置修复清单（先于自动化上线）

## 10. 错误处理与降级总表

| 故障 | 行为 |
|---|---|
| 周任务取数失败（MCP 不可用） | 通知「本周选题任务失败 + 原因」，不产出半成品清单 |
| 达标选题 <10 且池也不够 | 有几个给几个，清单头部标注缺口与原因 |
| image-gen 出图失败 | 配图位占位，流程继续 |
| 草稿箱推送失败 | 存本地成品 + 通知手动上传（含排版后 HTML） |
| 脱敏 grep 命中 | 硬停，列出命中行，等人处理 |
| 润色模型不可用 | 跳过润色，标注「未去 AI 味」，不用原模型自润充数 |

## 11. 实施验证方式

1. **dry-run**：手动触发 runbook 跑一次真实周数据，人工检查选题卡是否达标（证据真实、红线无违规）
2. **全链路演练**：选 1 张卡走完整流程到草稿箱 + 后台打开，验证 3 个确认点都停得住
3. **脱敏验证**：在测试稿里故意埋 2 个黑名单词，确认 grep 拦截生效
4. **降级验证**：断开 image-gen 验证配图占位路径
